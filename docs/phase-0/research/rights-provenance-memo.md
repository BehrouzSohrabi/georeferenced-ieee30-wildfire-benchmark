# Phase 0 rights, licensing, and upstream-provenance memo — wildfire-grid benchmark

**Scope.** A conservative, pre-release screen for a public benchmark drawing on an IEEE 30-bus case, LANDFIRE landscape layers, NREL NSRDB weather data, FARSITE, MATPOWER/ICSEG case data, and the IEEE Access article DOI [10.1109/ACCESS.2024.3439724](https://doi.org/10.1109/ACCESS.2024.3439724). This is a provenance-and-license research memo, **not legal advice**. It makes no determination of copyright, database, contract, trademark, privacy, export-control, or grant rights.

**Method and evidence boundary (11 Oct 2026).** Only first-party/official publisher, project, government, or license pages below were used. No data, software, or article files were downloaded; this is not a release authorization. Direct HTTP verification returned success for the non-NREL citations listed below (IEEE Xplore returned its normal asynchronous `202` response); the environment could not resolve `nsrdb.nrel.gov`, so its official URLs are recorded from official-search discovery and must be reopened during release review. “No license found” means no explicit redistribution license was located on the cited official page in this limited Phase 0 screen—not that none exists.

## Release posture: do not publish a bundled benchmark yet

The key blocker is not the MATLAB/solver code: it is the **case-data and input-data chain**. MATPOWER expressly says its BSD-3-Clause license does **not** cover its distributed case files. ICSEG’s IEEE-30 page is an authoritative provenance lead, but its page alone does not provide a machine-readable redistribution license. The official pages located for LANDFIRE, NSRDB, and FARSITE establish the source/provenance but do not, in this review, establish one uniform, release-ready license for every selected version/file/output. Treat every raw input and every copied parameter table as **not cleared for public redistribution until its exact item/version and terms are recorded and reviewed**.

A safer Phase 0 architecture is: (1) publish original code and original benchmark schema under a project-selected license; (2) supply a manifest that identifies exact upstream version, URL, checksum, retrieval date, and required citation; (3) require the user to obtain upstream inputs from authoritative sources; and (4) publish only independently created outputs after the output/right-to-redistribute question has been documented for each upstream dependency. This is a risk-reduction option, not a conclusion that it eliminates all obligations.

## Non-negotiable Phase 0 gates

1. **Freeze provenance.** Choose exact upstream releases/files; do not describe an arbitrary “IEEE 30,” “LANDFIRE,” or “NSRDB” input as if it has one universal license.
2. **Separate code from case data.** In particular, do not rely on MATPOWER BSD-3-Clause for case data; MATPOWER’s official page says it does not cover those files.
3. **Do not incorporate the IEEE paper as benchmark content.** Do not bundle/modify its PDF, visuals, tables, prose, or unseparated supplemental assets under a public benchmark release. CC BY-NC-ND 4.0 is unsuitable for a package that needs commercial reuse or shared adaptations absent a separate permission.
4. **Build a per-asset evidence packet.** For every item proposed for release, retain the exact official source/metadata/terms, version, access date, any in-file notice, and proposed attribution. “No terms located” is a release-stop state, not a presumed permission.
5. **Get a human release decision.** Grant terms, sponsor/funder rules, employment/institution IP policy, export/security policies, contributor agreements, coauthor consent, and any required upstream permissions require **human confirmation** by the appropriate authorized people. This memo cannot supply it.
